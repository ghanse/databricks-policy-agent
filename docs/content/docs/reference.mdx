This page provides a reference for the options supported by the policy agent.

## Resource types
Policies target one of the following resource types.

| Resource type       | Description                       |
|---------------------|-----------------------------------|
| `job`               | Databricks Lakeflow Jobs          |
| `cluster`           | All-purpose compute clusters      |
| `sql_warehouse`     | SQL warehouses                    |
| `app`               | Databricks Apps                   |
| `serving_endpoint`  | Model serving endpoints           |
| `catalog`           | Unity Catalog catalogs            |
| `schema`            | Unity Catalog schemas             |
| `volume`            | Unity Catalog volumes             |
| `registered_model`  | Unity Catalog registered models   |
| `external_location` | Unity Catalog external locations  |
| `quality_monitor`   | Unity Catalog quality monitors    |
| `secret_scope`      | Secret scopes                     |
| `genie_space`       | Genie spaces                      |
| `pipeline`          | Spark Declarative Pipelines       |
| `database_instance` | Lakebase database instances       |

<Callout type="info" title="Adding new resource types">
You can add custom resource types for any resources that aren't supported.
See [Adding a resource type](/docs/scanning#adding-a-resource-type).
</Callout>

## Resource attributes
Rules check that resource attributes comply with a specific policy. Each resource type exposes both 
common and type-specific attributes. A type only advertises valid resource attributes.

### Common attributes

| Field name     | Description                                                                  |
|----------------|------------------------------------------------------------------------------|
| `id`           | System-assigned resource identifier                                          |
| `name`         | User-assigned resource identifier                                            |
| `owner`        | Resource owner principal (e.g. a user or service principal)                  |
| `owner_type`   | Resource owner principal type (e.g. "user", "group", or "service_principal") |
| `created_time` | Date and time when the resource was created                                  |
| `tags`         | User-assigned key-value pairs                                                |

### Job attributes

| Field name                | Description                                                                 |
|---------------------------|-----------------------------------------------------------------------------|
| `schedule_pause_status`   | Indicates that the job's schedule is currently active or paused             |
| `max_concurrent_runs`     | Maximum number of concurrent runs of the job                                |
| `timeout_seconds`         | Maximum job run duration in seconds before the job is failed due to timeout |
| `run_as_type`             | Run-as principal type (e.g. "user" or "service_principal")                  |
| `has_email_notifications` | Whether the job specifies notifications on start, completion, failure, etc. |
| `has_retry_policy`        | Whether the job specifies a number of retries                               |
| `uses_serverless_compute` | Whether the job tasks use Databricks serverless compute                     |
| `format`                  | The job definition format (e.g. "SINGLE_TASK" or "MULTI_TASK")              |


### Cluster attributes

| Field name                | Description                                                                 |
|---------------------------|-----------------------------------------------------------------------------|
| `cluster_source`          | How the cluster was created (e.g. "UI", "JOB", "API")                       |
| `autotermination_minutes` | Minutes of inactivity after which the cluster auto-terminates (0 disables)  |
| `spark_version`           | Databricks Runtime version running on the cluster                           |
| `node_type_id`            | Cloud instance type of the cluster's nodes                                  |
| `num_workers`             | Number of worker nodes                                                      |
| `data_security_mode`      | Cluster access mode (e.g. "SINGLE_USER", "USER_ISOLATION")                  |
| `single_user_name`        | Principal a single-user cluster runs as                                     |

### SQL warehouse attributes

| Field name                  | Description                                                               |
|-----------------------------|---------------------------------------------------------------------------|
| `warehouse_type`            | Warehouse type (e.g. "PRO", "CLASSIC")                                    |
| `cluster_size`              | Warehouse size (e.g. "2X-Small", "Small", "Medium")                       |
| `auto_stop_minutes`         | Minutes of inactivity before the warehouse stops (0 disables)             |
| `enable_serverless_compute` | Whether the warehouse uses serverless compute                             |
| `min_num_clusters`          | Minimum number of clusters the warehouse scales down to                   |
| `max_num_clusters`          | Maximum number of clusters the warehouse scales up to                     |

### App attributes

| Field name               | Description                                          |
|--------------------------|------------------------------------------------------|
| `app_status`             | Current application state                            |
| `compute_status`         | Current state of the app's compute                   |
| `active_deployment_mode` | Deployment mode of the app's active deployment       |

### Serving endpoint attributes

| Field name         | Description                                                        |
|--------------------|--------------------------------------------------------------------|
| `endpoint_state`   | Readiness state of the endpoint                                    |
| `endpoint_type`    | Type of the serving endpoint                                       |
| `budget_policy_id` | Budget policy attached to the endpoint for cost attribution        |
| `route_optimized`  | Whether the endpoint is route-optimized                            |

### Catalog attributes

| Field name       | Description                                                          |
|------------------|----------------------------------------------------------------------|
| `comment`        | Free-text description of the catalog                                 |
| `catalog_type`   | Catalog type (e.g. "MANAGED_CATALOG", "DELTASHARING_CATALOG")        |
| `isolation_mode` | Whether the catalog is open or isolated to specific workspaces       |
| `storage_root`   | Cloud storage root where the catalog's managed tables are written    |

### Schema attributes

| Field name     | Description                                     |
|----------------|-------------------------------------------------|
| `comment`      | Free-text description of the schema             |
| `catalog_name` | Name of the catalog the schema belongs to       |

### Volume attributes

| Field name     | Description                                     |
|----------------|-------------------------------------------------|
| `comment`      | Free-text description of the volume             |
| `catalog_name` | Name of the catalog the volume belongs to       |
| `schema_name`  | Name of the schema the volume belongs to        |
| `volume_type`  | Volume type (e.g. "MANAGED", "EXTERNAL")        |

### Registered model attributes

| Field name     | Description                                     |
|----------------|-------------------------------------------------|
| `comment`      | Free-text description of the model              |
| `catalog_name` | Name of the catalog the model belongs to        |
| `schema_name`  | Name of the schema the model belongs to         |

### External location attributes

| Field name        | Description                                             |
|-------------------|---------------------------------------------------------|
| `comment`         | Free-text description of the external location          |
| `url`             | Cloud storage URL the external location points to       |
| `credential_name` | Storage credential used to access the location          |
| `read_only`       | Whether the location is read-only                       |
| `isolation_mode`  | Whether the location is open or isolated to workspaces  |

<Callout type="warn" title="Unsupported common attributes for Unity Catalog objects">
Catalogs, schemas, volumes, registered models, and external locations expose `id`, `name`,
`owner`, `owner_type`, and `created_time`, but not `tags` — their tags are not scanned.
</Callout>

### Quality monitor attributes

| Field name           | Description                                                     |
|----------------------|-----------------------------------------------------------------|
| `table_name`         | Fully-qualified name of the monitored table                     |
| `output_schema_name` | Schema where the monitor writes its metric tables               |
| `monitor_type`       | Type of monitor (e.g. snapshot, time series, inference log)     |
| `has_schedule`       | Whether the monitor runs on a schedule                          |

<Callout type="info" title="Quality monitors are enforce-only">
Quality monitors have no APIs for listing. They are evaluated only from the bundle at deploy time,
never scanned. They expose only `id` and `name` from the common attributes.
</Callout>

### Secret scope attributes

| Field name     | Description                                                       |
|----------------|-------------------------------------------------------------------|
| `backend_type` | Backend storing the scope's secrets (e.g. "DATABRICKS", "AZURE_KEYVAULT") |

<Callout type="warn" title="Unsupported common attributes for secret scopes">
Secret scopes expose only `id` and `name` from the common attributes. They have no `owner`, 
`owner_type`, `created_time`, or `tags`.
</Callout>

### Genie space attributes

| Field name        | Description                                          |
|-------------------|------------------------------------------------------|
| `warehouse_id`    | SQL warehouse the space runs its queries on          |
| `description`     | Free-text description of the space                   |
| `has_description` | Whether the space has a non-empty description        |

<Callout type="warn" title="Unsupported common attributes for Genie spaces">
Genie spaces do not expose the `owner`, `owner_type`, `created_time`, or `tags` attributes.
</Callout>

### Spark Declarative Pipelines attributes

| Field name    | Description                                                                 |
|---------------|-----------------------------------------------------------------------------|
| `catalog`     | Unity Catalog catalog the pipeline publishes tables to                      |
| `schema`      | Unity Catalog schema the pipeline publishes tables to                       |
| `target`      | Hive metastore target schema the pipeline publishes tables to (legacy)      |
| `channel`     | Databricks Runtime release channel (e.g. "CURRENT" or "PREVIEW")            |
| `edition`     | Product edition of the pipeline (e.g. "CORE", "PRO", "ADVANCED")            |
| `continuous`  | Whether the pipeline runs continuously rather than on a trigger             |
| `photon`      | Whether Photon acceleration is enabled                                      |
| `serverless`  | Whether the pipeline uses serverless compute                                |
| `development` | Whether the pipeline runs in development mode                               |

### Database instance attributes

| Field name                    | Description                                                          |
|-------------------------------|----------------------------------------------------------------------|
| `capacity`                    | Compute capacity of the instance (e.g. "CU_1", "CU_2", "CU_4")       |
| `state`                       | Current lifecycle state (e.g. "AVAILABLE", "STOPPED", "STARTING")    |
| `node_count`                  | Number of nodes serving the instance (primary plus any secondaries)  |
| `pg_version`                  | Postgres major version the instance runs                             |
| `stopped`                     | Whether the instance is currently stopped                            |
| `enable_readable_secondaries` | Whether readable secondary (standby) nodes are enabled               |
| `retention_window_in_days`    | Days of point-in-time restore history the instance retains           |

## Operators
Leaf comparisons use one of the following operators.

| Operator                     | Usage                                                                              |
|------------------------------|------------------------------------------------------------------------------------|
| `equals`                     | Strict equality                                                                    |
| `not_equals`                 | Strict inequality                                                                  |
| `matches_regex`              | Regular-expression match against a text value                                      |
| `in`                         | Membership in a list of values                                                     |
| `not_in`                     | Not a member of a list of values                                                   |
| `exists`                     | The attribute is present (not null); The attribute value is ignored                |
| `absent`                     | The attribute is absent (null); The attribute value is ignored                     |
| `less_than`                  | Numeric attribute is less than the value                                           |
| `greater_than`               | Numeric attribute is greater than the value                                        |
| `contains`                   | The attribute contains the value                                                   |
| `has_tag`                    | The `tags` mapping contains the given tag key                                      |
| `missing_tag`                | The `tags` mapping does not contain the given tag key                              |
| `not_empty`                  | The collection or mapping (e.g. `tags`) has at least one entry                     |
| `owner_is_service_principal` | The owner is a service principal; The attribute value is ignored                   |
| `ttl_within`                 | Numeric attribute is greater than 0 and at most the value (e.g. auto-stop minutes) |

## Policy effects
Policies can have one of the following effects on resources.

| Effect  | Meaning                                                            |
|---------|--------------------------------------------------------------------|
| `allow` | The resource is compliant only when its rule matches (allow-list)  |
| `deny`  | The resource violates the policy when its rule matches (deny-list) |

## Enforcement levels
Each policy carries an `enforcement_level` that governs how a violation is treated. `advisory`
is the default when unspecified.

| Level      | Effect                                                        |
|------------|---------------------------------------------------------------|
| `advisory` | Report only; never blocks a deployment gate                   |
| `soft`     | Blocks the gate but can be overridden with a recorded reason  |
| `hard`     | Blocks the gate and cannot be overridden                      |

## Roles
Roles are granted to workspace groups. A user's effective roles are the union of the roles
mapped to their groups.

| Role              | Privileges                                                       |
|-------------------|------------------------------------------------------------------|
| `admin`           | All privileges, including archiving policies and managing roles  |
| `policy_author`   | Draft and submit policies for review                             |
| `policy_approver` | Approve or reject policies under review                          |
| `scan_runner`     | Run scans                                                        |
| `viewer`          | Read-only access                                                 |

## Policy lifecycle statuses
Policies move through the following statuses. Only `approved` policies are run by scans. See 
[Managing Policies](/docs/approvals) for more information about the policy lifecycle.

| Status      | Description                                              |
|-------------|----------------------------------------------------------|
| `draft`     | The policy is being created                              |
| `in_review` | The policy has been submitted and is awaiting approval   |
| `approved`  | The policy is approved and is run by scans               |
| `rejected`  | The policy was rejected and is not run                   |
| `archived`  | The policy was archived and is not run                   |

## Remediation statuses
Each tracked violation is a remediation item in one of these statuses. See
[Tracking Violations](/docs/remediation) for complete information about reconciliation.

| Status        | Description                                                        |
|---------------|--------------------------------------------------------------------|
| `open`        | A newly detected violation                                         |
| `in_progress` | Being reviewed or addressed by a resource owner                    |
| `resolved`    | Fixed, either manually or auto-resolved on a later scan            |
| `waived`      | Knowingly accepted after review                                    |
